# 付费方案规划：Free / Plus / Pro

状态：已确认方案（2026-10-25）：只设美元价；Free 每月 1,500 点；审查只给付费档；提供年付和加油包。支付、收款主体和渠道暂不对接。

## 1. 为什么现在需要

注册已对所有 Google 账号开放，每个账号都是独立作者。灵感、创作整理、知识整理、审查都调用服务端配置的模型（默认 DeepSeek `deepseek-flash`），费用由站点承担。现有限制只在单个会话或单本书上：

- 一个灵感会话最多 20 万 token；
- 知识整理的每日预算由作者自己设置。

一个账号可以无限新建会话和作品，所以单账号费用和全站费用都没有上限。本方案先解决这个问题，再在此基础上划分付费档。

## 2. 计量单位：AI 点数

所有模型功能统一按「点」计量，作者只需要看一个数字。

- 1 点 = 1,000 计费 token。
- 计费 token = 未命中缓存的输入 + 0.02 × 命中缓存的输入 + 4 × 输出。

系数取自 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing) 的高峰价（2026-10-25 查询）。`deepseek-flash` 高峰价为：输入未命中缓存 $0.30/百万，命中缓存 $0.006/百万，输出 $1.20/百万。按高峰价折算，1 点最多花费 $0.0003。非高峰时段价格减半，命中缓存更便宜，所以实际花费通常更低。

模型改价时只需调整系数，不改套餐。以后接入更贵的模型时用倍率换算，例如 `deepseek-v4-pro` 高峰输入价是 flash 的 4.4 倍，按 4.4× 扣点。

典型用量是估算值，正式上线前要用真实用量校准：

| 操作 | 典型 | 上限（现有单次限制下） |
| --- | --- | --- |
| 灵感对话一条消息（约 3 次模型调用） | 30–50 点 | 约 240 点（6 轮 × 32k 输入 + 2k 输出） |
| 创作整理一轮对话 | 约 8 点 | 约 20 点 |
| 知识整理一章（约 3,000 字） | 10–20 点 | 约 40 点 |
| 连续性审查一章（仅付费档） | 30–60 点 | 需先收紧输出上限，见 §6.3 |

规则：

- **审查只给付费档**：Free 账号看得到审查入口，点击后显示升级说明。不发送任何内容给模型，也不扣点。理由：审查单次最贵，而且要把整章和相关历史章节一起发给模型。
- **写作永不受限**：写作和保存不消耗点数。点数用完只会暂停 AI 功能，不影响写作和已有内容。
- **不发生意外扣费**：
  - 每月点数按 UTC 自然月重置，不结转；每日上限按 UTC 日期重置。
  - 年付账号同样每月发放一次点数，不一次性发放全年额度。
  - 超出后直接停止，不会自动扣费。
- **从 Free 升级**：本月已用的点数照常计算，升级后按新档的月额度扣除。

## 5. 防滥用

注册一个 Google 账号几乎没有成本，所以只靠单账号额度不够，还需要全站层面的保护：

- **全站 Free 每日上限**：全部 Free 账号当天合计不超过 `WRITER_AGENT_FREE_DAILY_POINTS`（建议从 200,000 点起，最坏约 $60/天）。达到上限后，Free 账号当天暂停 AI 功能，付费账号不受影响。
- **紧急开关**：一个配置项即可暂停全部 Free 档 AI 功能，或暂停全部 AI 功能。写作不受影响。
- **新账号冷启动**：注册当天的每日上限减半。
- 如果出现批量注册，在登录页加 Cloudflare Turnstile。
- 每日费用汇总写入日志。超过预期时，人工或用告警停用 Free 档。

## 6. 技术方案

### 6.1 记账

新建 `internal/billing`，复用现有的文件锁和原子 JSON 写入模式：

- 每个作者一个文件 `state/billing/accounts/<作者键>.json`，内容包括：套餐、计费周期（月付或年付）、来源（free / manual / payment）、有效期、本月已结算与预留点数、当日用量、加油包列表（剩余点数和到期时间）、最近一次登录邮箱（用于管理员查找），以及按操作 ID 记录的流水（有上限）。
- 全站计数存在 `state/billing/free-pool/<日期>.json`；账户、全站池与兑换码由同一个内核文件锁和可恢复提交日志保护。
- API 进程和 Worker 进程共用状态目录，跨进程靠现有的 O_EXCL 锁保证正确。

每次模型调用分三步：

1. **预留**：调用前按保守上限预留点数，余额不足就拒绝。按操作 ID 幂等，重试不会重复预留。
2. **结算**：完成后按实际用量结算，把预留换成实际值。实际用量缺失时，按预留值计。
3. **释放**：没有调用模型就失败时，释放预留。预留超过任务租约期限会自动释放，进程崩溃也不会永久占用点数。

### 6.2 在哪里拦截

所有调用都在 Go 中经过（作者身份已在 SEC-001 中按用户隔离），各类调用的处理方式：

| 功能 | 预留时机 | 结算来源 |
| --- | --- | --- |
| 灵感消息 | Go 把消息转发给 Pi 之前 | Pi 会话快照里的 `usage`（对账循环已在读快照） |
| 创作整理、计划核对 | 任务入队或领取时 | `llm.Response.Usage` |
| 知识整理 | `Claim` 时，与每本书现有的每日预算叠加 | 同上 |
| 审查（仅付费档） | 创建审查时（作者已确认发送范围之后）；Free 直接返回 `402 PLAN_FEATURE_REQUIRED` | 同上 |

额度不足时，不同调用方式的表现：

- **作者主动发起的操作**：返回 `402 PLAN_QUOTA_EXCEEDED`，附带剩余点数和重置时间。界面显示「本月 AI 点数已用完，写作不受影响」和方案页入口。
- **后台任务**：标为「等待额度」，不算失败，额度恢复后自动继续。

### 6.3 先收紧的上限

- **审查预留**：现在按 `MaxContextBytes + 20000 + MaxOutputTokens` 预留，而 DeepSeek 默认输出上限是 131072，一次就要预留约 600 点。上线计费前需按套餐把审查输出上限收紧到 4096 左右。
- **灵感单次请求上限**：按套餐设置轮数、输入、输出上限，例如 Free 4 轮 / 24k。这需要 Pi 在建会话时接收每个会话自己的上限（小改 Pi 的会话创建接口）。

### 6.4 接口与界面

- **`GET /v1/account`**：返回套餐、本月和当日用量、剩余点数、重置时间。Worker 加对应路由。
- **顶栏**：显示点数（「本月 1,234 / 6,000」）。账户页显示用量明细和三档对比。在支付对接前，升级按钮显示「即将开放」，或填写兑换码。
- **管理员工具**：在 `writer-agent-control` 增加以下命令，用于支付对接前的开通、内测和退款处理：
  - `billing grant --email … --plan plus|pro --interval month|year`
  - `billing topup --email … --points 3000`
  - `billing usage --email …`
  - 兑换码生成与核销
- **顺带修复**：`GET /v1/agent-runtime` 现在返回全站汇总的任务数，应改为只返回当前作者的数量。

### 6.5 测试

需要覆盖：

- 并发预留不会超额；
- 重试时幂等；
- 结算多于或少于预留；
- 崩溃后预留自动释放；
- 跨月和跨日重置（UTC）；
- Free 账号发起审查被拒绝，且不发送内容、不扣点；
- 加油包的扣减顺序、到期和降级冻结；
- 全站 Free 上限和紧急开关；
- 后台任务等待额度后能恢复；
- 双账号互不扣点；
- 灵感、知识、审查、创作四条路径各有一条端到端测试，不调用付费模型。

## 6.6 阶段 0 实现说明（2026-10-25）

已实现：

- **记账**：新包 `internal/billing`，按本文 §6.1 的预留 → 结算 → 过期计费流程。
- **准入规则**：已结算用量加上未结算的预留低于上限时，才允许新的调用。因此一个账号最多超出一次调用的实际用量。
- **四条模型调用路径**：
  - 灵感：Go 在转发消息前预留点数，并按 Pi 报告的累计用量结算。
  - 知识、审查、创作：在领取任务时预留，在完成时结算，Go Worker 和 Pi Worker 两种执行方式都覆盖。
- **审查**：在预览阶段就对 Free 返回 `402 PLAN_FEATURE_REQUIRED`，不会发送任何内容。
- **全站 Free 每日池**和**暂停开关**：共享状态，API 和 Worker 进程都读同一份。
- **`GET /v1/account`**：Worker 只放行 GET。
- **顶栏点数与方案说明**：在窄屏（< 640px）上隐藏；额度不足时仍由 402 提示说明。
- **旧数据所有者**：`WRITER_AGENT_AUTHOR_ID`（即 bluedao10000@gmail.com 继承的身份）默认按 Pro 计。

与原计划不同的地方：

- **单次上限没有改**。原计划在阶段 0 收紧审查和灵感的单次上限，但审查输出上限包含 DeepSeek 的推理 token，收紧有截断风险。所以不改模型请求参数，只用上面的准入规则控制，单次超出的上限就是一次调用的实际用量。灵感的按套餐单次上限需要改 Pi，留到阶段 1。
- **`/v1/agent-runtime` 没有改**。它不在 Worker 放行的路由里，浏览器访问不到；而 Go 要求签名用户声明，外部也无法直接调用。所以不存在跨账号暴露，这次不修改。
- **作品数、并发会话、EPUB 导入次数等非 AI 限制**，以及管理员开通套餐，都留到阶段 1。

运维命令要以服务用户运行，否则生成的文件 API 无法读取，AI 功能会因此全部拒绝：

```sh
sudo -u writer-agent /opt/writer-agent/current/writer-agent-control --state /var/lib/writer-agent --billing
sudo -u writer-agent /opt/writer-agent/current/writer-agent-control --state /var/lib/writer-agent --ai-pause free   # none / free / all
sudo -u writer-agent /opt/writer-agent/current/writer-agent-control --state /var/lib/writer-agent --free-daily-points 100000
```

## 6.7 阶段 1 实现说明（2026-10-25）

已实现：

- **方案与期限**：账户记录方案、月付或年付、来源（manual / code / payment）和到期时间。同一方案再次开通从原到期日顺延；换成另一方案从当时起算。到期后回到默认方案：普通账户为 Free，旧数据所有者为 Pro。年付同样按 UTC 自然月发放点数。
- **加油包**：先用完每月点数，再按到期时间从早到晚扣加油包。自发放起 12 个月有效。Free 账户下保留但冻结，不能使用，也不计入额度；再次升级后恢复。加油包不提高每日上限。到期 40 天后从账户文件中清除。
- **管理员开通与兑换码**：`writer-agent-control billing usage|grant|topup|codes`，命令见部署指南。
  - 兑换码格式为 `WA-XXXX-XXXX-XXXX-XXXX`，80 位随机数，只保存摘要。
  - 同一账户重复兑换同一个码不会重复发放，其他账户使用会得到 `CODE_USED`。
  - 已有其他有效付费方案时，兑换方案码会得到 `409 PLAN_CONFLICT`。Free 账户兑换加油包码会得到 `402`。
  - 每个账户每天最多输错 10 次。
- **账户页**：页头「AI」打开「账户与方案」，显示方案与到期日、今日和本月点数、加油包、本月按功能的用量和最近 20 次记录、方案限制与当前用量、三档对比和兑换码输入框。升级按钮显示「即将开放」。
- **非 AI 限制**：超出时返回 `402 PLAN_LIMIT_REACHED`，已有内容不受影响。
  - 作品数：Free 3、Plus 30、Pro 300。新建作品和 EPUB 导入都检查，改名、加章等编辑不受限。
  - EPUB 导入：Free 每月 2 次，按提交导入计数，在上传阶段提前提示，在提交时最终检查。删除导入的作品不会退回次数。
  - 同时回复的灵感会话：Free 1、Plus 2、Pro 4。一个会话从发送消息到 Pi 报告这一轮结束之间算「回复中」。两个会话在同一瞬间发出各自的消息时都可能通过，所以最多超出 1 个。
- **Pro 优先**：Go Worker 和 Pi Worker 领取后台任务（知识整理、审查、创作整理）时，Pro 作者的作品先领取。每三次领取有一次忽略优先级，按普通轮转进行，所以一位 Pro 作者积压大量任务时，其他作者的任务也不会一直等待。
- **`GET /v1/account`** 增加了方案期限、加油包、用量明细、方案限制、作品与导入计数和价格目录。**`POST /v1/account/redeem`** 用于兑换，Worker 只放行这两个路由。
- **计费持久化**：计费使用持久 inode 上的内核 `flock`，进程退出自动释放锁，禁止按文件年龄抢锁。账户、全站池、兑换码的最终状态先写入 `billing/pending-v1.json`，再逐文件落盘；每次计费读取或写入先恢复未完成提交。
- **缓存计点**：Go 与 Pi 都采集缓存命中输入；按 `ai-points-cache-v1` 规则用整数计算，最后统一向上取整。缓存字段缺失、越界或冲突时不打折；无法取得完整 Usage 时保持保守预留。
- **升级要求**：锁协议变化时必须停止所有旧版计费写入进程（API、Go Worker、Pi Worker 以及管理员 CLI），完整备份后一起升级。回滚到旧锁协议前，先在新版下完成日志恢复并停止写入；不得删除 mutex、提交日志或用旧账户备份覆盖新流水。详情见 [审查修复记录](../reviews/pricing-phase1-review-fixes.md)。

暂未实现：

- **新账号冷启动**（注册当天每日上限减半，§5）：没有可靠的「注册时间」，账户文件在首次打开作品台时才创建，因此暂缓。
- **灵感单次请求按方案设上限**（§6.3）：需要改 Pi 的会话创建接口，留到后续。
- **管理员按邮箱查找**依赖作者登录后打开过作品台；从未打开过的账户无法查到。
