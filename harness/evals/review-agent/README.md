# 证据审查评估

`cases.json` 是隔离的诊断短句，不是作者作品。每例包含当前输入、历史记录、审查类型、预期行为、禁止行为和替身模式。测试运行时才在临时目录生成 Harness，退出后清理。

## 三种证据分开报告

1. `pnpm eval:review`：真实 Go HTTP API → HTTP 替身 → JSON 与引用校验 → 状态持久化。它证明工程不变量，不证明模型识别矛盾的能力。
2. `pnpm eval:review:live`：发送合成夹具给本地配置的真实模型，需显式运行。不能自动判定语义质量。
3. 真实作者反馈：保存在 Review Run 应用状态，需积累样本后再报告比例。

## 人工评分表

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 证据覆盖 | 假来源 / 假引文 | 来源真实但不支持推断 | 至少两处相关原文 |
| 判断边界 | 确定作者写错 | 有不确定词但忽略视角 | 区分台词、叙述、认知 |
| 作者价值 | 无法行动或强制改稿 | 问题宽泛 | 具体可回答的问题 |
| 信息不足 | 补造事实 | 提示不确定但无证据 | 空结果或不作为已核验发现展示 |

## 工程硬门槛

非法来源接受数、未授权正文修改、未确认设定自动写入、主动打断输入均要求为 0。所有展示为核验通过的引文必须精确命中授权快照。失败不得回退 Demo 或声称已完成。
