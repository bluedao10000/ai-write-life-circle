# Knowledge 容量修正

2026-10-22 只读统计生产 Revision，共 171 章。UTF-8 正文字节中位数 11,853，
P90 16,399，P95 21,381，P99 25,738，最大 37,038。统计未复制正文。
12,000 字节的整请求上限会拒绝正常中文章节，不能解释为 12,000 Token。

默认整请求输入改为 65,536 字节（包含 JSON 元数据，不截断正文），配置上限
262,144 字节。正确命名的 WRITER_AGENT_LLM_MAX_CONTEXT_BYTES 优先于旧
WRITER_AGENT_REVIEW_MAX_CONTEXT_TOKENS；旧变量仍按字节解释，显式值保留。
Review 和 Knowledge 共用此模型执行配置，API、Go Worker 与 Pi Worker 必须同步。

DeepSeek 默认输出提高为 131,072 Token，最大可配置 131,072；
Go 校验、Pi 执行配置及 Usage 契约同步。其他 Provider 默认输出仍 2,048。
Knowledge 候选上限提高为 512 KiB，HTTP 响应体上限为 1 MiB；JSON 不完整仍失败，
不能保存残缺知识。线上 32K 配置中 `CH-000083`、`CH-000084` 已分别产生
23,882、22,540 输出 Token，`CH-000085` 仍因输出截断失败，因此 32K 不能覆盖
实际长章。固定合成短句能力探测确认 DeepSeek 接受最高 131,072 的 `max_tokens`；
本轮没有发送小说正文到探测请求，也没有用增大容量替代语义验收。

预算保守预留仍采用输入字节数 + 20,000 + 输出 Token 上限，字节数作为
Token 数上界，避免中文低估。默认配置每次预留 216,608 Token，
已知 Usage 返回后按原规则结算；未知 Usage 保留预留。
新授权 UI 默认 100,000,000 Token / 200 次。两项取先到上限者，失败和重试也计次。
已有作品额度保留，尤其不能自动提高作者已批准的每日次数。

部署核对：
- 显式旧环境若仍为 12000，默认值不会覆盖；API/Worker 同时设置新字节变量 65536、
  输出 131072，核对配置兼容。Pi 有独立覆盖变量时也需同步。
- 现有失败不自动重新执行。先在新版本和新容量下确认作者模型授权/额度，再通过
  领域重建接口重新入队；禁止直接编辑任务状态文件或清空预算账本。
- 当前线上 20 次每日额度需作者改为 200 次，不能单改 Token 上限。
- 当前实测全部章节落在输入容量内；未来超过上限仍明确失败，超长章分块另行实现。
  本轮没有实现跨分块实体归并或声称支持任意长度章节。
- 32K 容量变更已部署，长章样本证明仍会截断；131072 修复部署后继续观察输出
  完整率和任务推进。
