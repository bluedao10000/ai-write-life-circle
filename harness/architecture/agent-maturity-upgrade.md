# ADR：Agent 成熟度升级

日期：2026-11-04。审计基线：25e6066。状态：Phase 0 设计完成，后续实现待验收。

## 决策

保留 Go API、Pi Thinking、Pi Worker 三进程。Go 管理作者、作品、正式写入、点数、授权和任务领取；Pi 管理受控执行和候选。治理层只统一合同与执行边界，不增加任务权威、数据库或账本。

Thinking 的 Saved/Run 与 Durable Task、Worker 的 Go AgentTask 保持各自状态。公共生命周期是只读映射，不持久化一份平行状态。新增能力必须通过现有模型和工具入口，不能直接创建 Provider 客户端。

## 实施顺序

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0 | 能力审计、复用清单、六份设计文档 | 权威归属与迁移边界明确 |
| 1 | Registry、执行上下文、模型/工具治理、授权/预算适配、审计 | Thinking 与四种 Worker 任务均接入；原测试及真实进程故障测试通过 |
| 2 | 五类评测、独立 dev/held-out、评分与版本化报告 | 全部既有 Agent 有实际执行轨迹；未测指标为 null |
| 3 | 四层记忆、来源/审核/冲突/过期/删除 | 隔离、撤销及重启回归通过；候选不自动成为事实 |
| 4 | 诊断、有限基数指标、攻击集 | 注入、扩权、跨作者及重复副作用测试通过 |
| 5 | Creative 只读角色编排试点 | 同任务单/多角色可比，父预算、权限和取消约束通过 |
| 6 | 有界计划执行 | 前述验收完成；每步有终止条件与有效审批 |

每阶段独立提交，能力状态以 agent-maturity-report.md 的证据为准。确定性模型仅证明工程约束；真实能力报告必须来自显式授权、合成数据、有限费用的真实模型评测。

## 数据与发布

Phase 0 不改变数据。Phase 1 优先用既有状态派生上下文；确需记录运行版本时仅在原权威对象内增加可选字段，旧记录标记 legacy，不能推断为当前策略。审批、记忆或计划若需新持久字段，先提供旧数据 fixture、重启、墓碑、未知费用与回滚测试，再启用写入。

保持 layout=2 的双库停机备份要求。兼容回滚保留新费用、回执与删除记录；不能以旧备份覆盖开放流量后的数据。按现有 pi-agent/pi-worker 发布流程先验证隔离副本，再切换发布，分别验证 liveness/readiness/degraded。该阶段不授权远程发布或真实付费模型调用。
