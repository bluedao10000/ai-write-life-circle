# ADR：作者作品管理

状态：在线作品管理基础已上线。生产迁移不自动执行。

## 权威与兼容

`<WRITER_AGENT_STATE_DIR>/works/catalog-v1.json` 是受信任的作品注册表和结构权威。它保存所有权、稳定 ID、有序卷与章节、归档状态、结构版本、幂等回执和审计记录。它不含正文。一次原子 fsync/rename 提交整个操作，包括创建默认作品和第一章。

受管理章节用不可变空封套（`# 第一章`、稳定 CH ID）填充现有 Harness Parser。可变标题、卷和顺序叠加在解析投影上，不改变 source hash、blob 或正文。空源 Revision 立即可寻址。首次正文保存使用现有 Revision CAS 和原子草稿文件。内部标题从不进入编辑器。

配置的外部 Harness 和现有 project ID 保持注册且不变。其结构只读。不做 chmod、自动导入、移动或来源调和。空的外部 Harness 不出现在创建菜单中。在线 Get/Resolve 直接校验注册表所有权，不通过 List 扫描旧资料。聚合作品列表仅为配置作者尽力加载兼容资料；读取失败时省略该兼容项，不阻断在线作品，显式访问旧作品仍返回原错误。

## 隔离与并发

认证作者 ID 拥有作品。请求中的 ownerId、root、path 字段被拒绝。每个动态项目请求先经注册表解析，再使用现有应用、Notes、Review、Publication 服务。Review worker 按受信任作品缓存，关闭时清理。

卷和章节使用稳定 ID。数组位置是显式持久化顺序。未分组章节排在卷之前。空卷存在于注册表中。完整结构更新必须保留每个章节 ID 恰好一次。归档保留 ID、草稿、审查历史和公开快照。非空卷不能删除。

所有结构写入要求 baseVersion 和 Idempotency-Key。同键同体重放原结果。不同体重放被拒绝。Catalog O_EXCL 锁串行化进程。结构变化保守地使旧证据过期，不改正文 lineage。

## 永久删除

`DELETE /v1/studio/books/{bookId}` 校验作者所有权、baseVersion 与 Idempotency-Key。公开作品先下架；外部 Harness 禁止删除。Catalog 原子移除作品并保存带 owner 的删除墓碑及待清理标记，随后清理正文修订、笔记、审查、知识、工作台偏好、已提交 EPUB 暂存和发布状态；保留最小审计与幂等回执。原创建/导入请求不能恢复已删除作品。

受管理作品的资源事务使用 works/resource-locks 中的稳定锁。最终写入在 works/book-commits 的作品锁内重新校验注册表；删除后已解析的请求和迟到 Agent 结果不能重新落盘。清理与最终写入共用作品锁，资源锁不在清理范围。锁顺序为资源锁 → 短暂作品写入锁；清理释放作品锁后才获取导入/发布锁，避免与发布持有的章节锁循环等待。已发送的模型请求可能仍在远端执行，但删除后结果无法提交。

清理失败时作品保持不可见，标记保留。相同请求可重试，API 启动时也会恢复待清理删除。浏览器移除本作品的章节恢复草稿并刷新作品列表。其他设备的本地恢复副本不受服务器控制。

## 生产升级、备份与回滚

所有新文件在现有 systemd StateDirectory `/var/lib/writer-agent` 内。外部 `/srv/writer-agent/harness` 保持只读。专用服务账号拥有新的 0700 目录和 0600 文件。

升级前停止 API，备份整个状态目录、现有 Harness、root-only 环境、服务 unit 和 release 软链接。先在隔离目录恢复快照并验证，再改生产。新增管理路由时先部署 Go；可选响应字段的滚动兼容顺序见[部署指南](../deploy-guide.md)。

程序回滚和数据回滚不同。回滚前停止写入并做新的完整备份。旧二进制不能枚举受管理作品，但不得删除注册表或草稿文件。优先向前升级。若必须恢复旧程序，禁用受管理写入并保留所有新状态。绝不用升级前备份覆盖活动状态目录。
