# Agent 长对话上下文管理

## 根因与复现

原 runtime 持久化并完整重放 SessionManager entries，工具 JSON、SDK 元数据及失败轮次也继续增长。SDK automatic compaction 显式关闭，以避免 SDK 在应用授权、计费和调用次数控制之外调用模型。旧手动 compact 已被可靠性修复关闭；恢复旧 checkpoint 不会降低输入。

inputBound 实际为 JSON 的 UTF-8 字节数 + 4096，属于保守 Token 上界，不是 tokenizer。中文每个字符通常占多个字节，较早触发限制。模型窗口和应用输入上限不同；本修复保持原输入上限，未以提高限制解决问题。

受控回归构造 80 条长中文消息，原算法超过 32000 字节；新增实际 Pi SDK 的 45 轮测试，验证整理事件、消息保留、模型切换、重启、幂等及授权拒绝。

## 原始历史与有效上下文

原始 view.messages 保持可查看，不删除消息。每轮重新创建实际 SDK SessionManager，只重放成功的可见讨论，不重放历史工具调用与失败 assistant 结果。SDK entries 是执行上下文，不是历史唯一来源。

discussionMemory 包含 summary 和已覆盖消息位置 through，独立存储于 Pi 私有会话文件，不能写 Creative Assets、Canon 或知识库。摘要通过 SDK custom message 进入上下文；每轮保留最近两组原始交流。旧上下文达到输入上限的 80% 时，在同一注册模型上逐批整理早期消息。

摘要输入自身受保守字节预算限制；输出最多 3000 UTF-8 字节，空摘要、过长、模型截断和显式无法安全整理均拒绝提交。所有整理成功且授权仍有效后，才原子写入新 memory；失败保留旧 memory、完整历史和当前问题。SDK 自动 compaction 继续关闭。

## 权威与来源

摘要提示要求区分作者决定、讨论假设、正文观察、重要分歧、未决问题和 source IDs。模型生成摘要的语义完整性仍需人工抽检。摘要是非可信讨论资料，不提供工具权限或正式设定权威。引用卡片必须由本轮授权工具重新获取并核验；历史来源标识只能作为查找线索。

模型切换继续使用同一作品的非可信讨论记忆，并通过当前模型重建 SDK context；不携带旧工具执行记录。授权缩减和撤销继续走现有 grant 验证和执行 fencing；摘要提交前也重新验证授权。

## 调用、费用与失败

整理走同一个 runtime.streamSimple 包装器，使用原模型、凭据、deadline、会话累计额度、真实 Usage、保守未知费用及调用上限。普通无工具轮最多两次模型调用，Go Billing 预留同步覆盖两次，未使用部分按真实用量结算。工具轮仍受原总调用上限约束；整理不提供额外无限调用。

长历史可能需多批整理；调用或累计额度不足时停止，不清空历史以伪装成功。显式续谈要点优先于旧 memory，重试不再重新载入完整旧历史。前端为恢复表单预填最近讨论，作者确认后继续；这份草稿只包含当前已加载消息，不能代表完整历史摘要。

前端区分输入整理失败、累计额度、输出截断、超时和模型故障。compaction 事件包含“正在整理讨论上下文”和“正在继续回复”；原始错误码保留供排查，正文不再统一显示“未生成完整分析”。

## 验收与边界

执行 Agent 全量测试、Go Thinking 计费/隔离测试、Web 测试、TypeScript 与 Lint。context-management.test.ts 使用实际 SessionManager、AgentSession 和本地 HTTP 模型，覆盖 45 轮中文、摘要持久化、恢复、模型切换和失败历史保留；不以本地合成回复证明摘要文学质量。

现有消息存储上限、单条超大问题、单次超大工具返回、累计会话额度仍保留；这些情况不能通过摘要免费绕过。生产部署及真实模型调用需单独执行，本分支不自动执行。
