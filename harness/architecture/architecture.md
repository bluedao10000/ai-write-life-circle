# 架构决策

日期：2026-09-25。范围：单作者。AI 管理并提供启发，正文由作者书写。

## 决策

v0.1 使用 Markdown harness + Git + 任意文件型 Agent。暂不开发 pi SDK 应用。pi CLI 也可作为执行器，两者不互斥。

| 维度 | 文档 harness | pi SDK 应用 |
| --- | --- | --- |
| 初期成本 | 维护约定和资料 | 维护运行时、工具、模型接入 |
| 跨编辑器 | 高 | 需额外接入 |
| 作者控制 | diff、提案、逐项确认直观 | 需实现确认界面 |
| 硬性权限 | 提示词是约定，不强制 | 可在工具层实施 |
| 重复批处理 | 人工启动，易遗漏 | 可队列化、重试 |
| 检索规模 | 索引与文本搜索 | 可增量索引、全文搜索 |
| 持久状态 | 显式文档与 Git | 会话数据库需与文档一致 |

## Harness 职责

入口约束、按任务取上下文、文件状态、操作流程、可追溯证据、人工决策、评估反馈。

它不把所有资料塞进 AGENTS.md。模型上下文和聊天压缩不能替代书籍档案。

## 数据流

作者正文 → 保存 Revision → 已授权的 AI 自动提取与来源核验 → 私有衍生知识与索引 → 检索和审查。日常观察无需逐项审批；只有正式设定的创作裁决进入候选提案 → 作者决定 → 正式资料。详见 [AI 作品记忆](ai-knowledge-memory.md)。

外部作品 → 有出处的案例 → 表达机制比较 → 启发问题。外部作品不直接进入小说事实库。

## 边界和风险

Markdown 不提供强制访问控制。使用编辑器权限限制、工作副本与 Git diff 检查。不要把 AGENTS.md 当作安全沙箱。正文备份与提交前 diff 是最低保护。

多模型同一时间仅一个写入者。若需并发，使用独立分支或工作树，人工合并后检查一致性。

索引与摘要可能过期。提取带内容 hash，接受前核对正文。读者分析需回到原文。

不设 AI 自动发布章节、自动决定剧情、自动演化作者风格的闭环。

## 何时升级

先以 5–10 章验证。只有出现重复需求再增加：静态检查（断链、重复 ID、失效 hash）、SQLite FTS 增量检索、pi 执行层。

## 评估

硬指标：正文未授权修改 0 次；正式设定未确认写入 0 次；已核验引用可追溯率 100%。软指标：意图理解获认可、案例有启发、维护耗时下降。不用模型自评分替代作者判断。
