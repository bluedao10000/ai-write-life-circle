# ADR：经验提取只产生作者待确认的记忆候选

日期：2026-10-29。更新：2026-11-05。状态：作者主动提取、后台经验整理、语义关系建议、来源/结果预览和候选审核已实现。

## 执行与权威

作者选取成功任务 → 同意发送 → 来源绑定的 Thinking Durable 执行 → 模型候选 → Go 验证并保存 → 作者独立确认。Go 继续拥有授权、点数、业务写入和幂等回执；Pi 负责受治理模型执行。复用现有会话和 Run，不新增任务数据库或预算账本。

主动提取使用专用 `memory.extract.v3` 角色与 `memory-extraction-v3` 提示。新会话绑定公开结果投影的稳定版本令牌；v1/v2 数字版本会话仍可加载，旧候选继续按原协议校验，但不能在 v3 运行时恢复出新的付费请求。后台整理使用第五种既有 AgentTask 类型 `memory.consolidate`，由 Go 原有领取、租约、执行权、回执和 Pi Worker 调度，不增加浏览器定时器或第二套任务权威。

## 来源与发送范围

作者创建会话时明确同意发送 1–4 个成功任务的原始来源、关联业务结果与作者反馈。Go 同时固定至多8条当前可检索的已确认操作经验及其版本，供同一模型调用比较；更多规则只返回省略数量，不能扩大比较集合。Go 保存任务/经验 ID 与版本，不保存来源正文副本。原章节读取任务的历史 Revision，Creative 讨论读取已保留摘录；来源最多16 KiB，结果最多20条与16 KiB，截断明确标记。Knowledge 标记为 revision_observations，不冒充单次模型输出档案。

每次授权和读取上下文重查作者/作品、来源可用性及结果版本。来源清除、反馈或结果变化阻止新调用与候选发布。模型不能改变任务集合、作者、作品或授权版本。上下文经 Pi 原 payload Token 上限和费用预留检查后才发送。

专用会话 scope 固定为空，不继承作品权限设置；禁止故事工具、自动整理、模型切换与正文选区。任务证据只作为引用数据，不能授予权限。提示说明证据局限，真正的边界由 Go 来源绑定、ModelRequestGate 和零工具策略执行。

## 候选发布与审核

模型输出严格 JSON：`content`、`taskIds` 与 `relations`。正文说明适用情境、方法和证据限制，最多4000 UTF-8字节；来源必须是本次选中任务的非空子集。`relations` 只能引用本次固定的已确认经验，类型限定为 `duplicate`、`conflict` 或 `refinement`，并保存简短理由与固定版本；无法确定或无关注释时省略。成功回执只证明执行，不证明关系判断、方法质量或因果关系。

作者调用 `POST /thinking/sessions/{id}/memory-candidate`，只提交 `runId`。Go读取 Pi 持久结果，核验完成状态、授权版本、来源版本和取消状态，拒绝浏览器提供模型正文或确认状态。通过原 Procedural 事务保存 candidate，幂等键为 Run 身份；重复命令不新增候选或模型调用。

候选的 `extractions` 保存会话、Run、模型、提示版本、授权版本和关系建议。关系建议没有确认、合并或替代副作用；工作台明确提示作者判断，目标经验版本变化或不可用后标为过期。合并精确相同候选时保留全部提取来源，最多8个任务及8次提取执行；不按语义相似度自动合并。确认、合并和检索仍验证原提取授权与来源。撤销、删除或来源版本变化使其不可用，不通过合并清除权限约束。

确认仍是作者独立 Go 命令，绑定候选版本；至少需要同 kind/strategyVersion、不同 taskId/inputHash 的两个成功输入。默认30天有效，最长90天。模型不能确认记忆、改变 Canon、修改预算或直接执行外部副作用。

## 后台经验整理

作者在 Creative 设置中显式开启 `autoMemoryConsolidation`。Go从本作品最近成功任务中选择2–4个同 kind、同 strategyVersion、不同 inputHash 且尚未被当前经验消费的来源；已经尝试过的来源组合不会因Provider失败、进程崩溃或任务重试再次自动发起。来源不足、设置关闭或预算不足时不创建任务。

`memory.consolidate`只执行一次无工具模型调用。上下文由有界原始来源、结果投影和至多8条当前可检索已确认经验组成；候选沿用4000 UTF-8字节上限，严格输出 `content/taskIds/relations`。任务开始、模型完成和候选发布都重读来源与公开结果版本；任一来源清除、反馈变化或版本变化都阻止发布。成功只创建candidate，仍需作者独立确认，不自动合并、替代或写入Canon。

费用复用 Creative 的原每日 token/job 预算和Go点数预留。任务ID是预算预留、结算和候选幂等身份；首次终态报告拥有结算权，Worker重复上报完成或失败不会重写已结算预算，未知Usage继续保留完整预留。设置、任务回执和候选均使用现有原子状态文件，没有新增数据库。

统一提取绑定使用 `sha256` 结果投影令牌作为版本，不把Knowledge全局文件版本当作单个任务结果版本。令牌只随公开结果项、状态、反馈和截断信息变化。旧 `memory-extraction-v1/v2` 的整数版本保留在兼容协议中，旧候选继续使用原数字版本校验；它们不能被新代码恢复为新提取，也不会被静默迁移成当前令牌。

## 取消、崩溃与恢复

沿用 Thinking 的取消 epoch、执行栅栏、未知费用保留、SIGKILL 启动中断和显式付费恢复。没有自动重试循环。取消同步可取得最新 grant 以终止 Pi 运行，但不能据此导入候选或开启新的提取。工作台只在作者点击后调用模型，网络结果不明时复用原请求身份。

## 数据兼容与回滚

原会话新增可选 `memoryExtraction`：v1/v2保留原数字结果版本与经验比较集合，v3改用稳定结果令牌并增加 `memory.extract.v3` 审计角色；原Procedural记录新增可选 `extractions.sources`、`relations`和后台整理来源。旧会话、旧候选和手工候选保持不变，没有新增存储文件或数据库。

后台任务加入现有 `tasks-v1.json` 的 `memory.consolidate` 类型，自动设置加入Creative设置的可选字段。旧Go和Pi不能读取这两种新数据，因此回滚不是直接替换二进制。

回滚步骤：

1. 停止新提取；取消仍运行的专用会话，等待费用结算或保留未知费用。
2. 撤回自动提取的候选/规则，包括保留提取来源的合并结果，防止旧代码跳过来源约束。
3. 使用新 `writer-agent-control --state <dir> --kind memory --owner disabled --wait <duration>` 停止并排空后台整理，保留费用和任务回执。
4. 停止Go、Pi和Worker；执行 `writer-agent-control --state <dir> --rollback-memory`。该离线命令只删除已结算的 `memory.consolidate` 任务、对应v3会话及其幂等键，遇到开放计费、未结算 intake、活动lease或非终态任务时拒绝写入。
5. 按现有停机备份流程备份状态，再回滚 Go/Pi。命令保留其他任务、候选、账单和业务回执；旧二进制不会把已移除的v3会话或后台任务复活。

真实兼容测试以 `15a241e` 的 Go/Pi 构建读取上述退役状态，验证进程启动、任务回执、已收费点数和零新增模型调用。测试入口：`scripts/test-memory-extraction.mjs --rollback-api=<old-go> --rollback-pi=<old-agent-entry>`。

## 验收与剩余范围

真实 Go/Pi + 本地合成 Provider 验证：明确同意、跨作者拒绝、固定来源/结果版本、固定经验比较集合、模型关系建议、未绑定目标拒绝、零工具、无效输出/额外来源拒绝、候选导入幂等、API/Pi 重启、取消、SIGKILL 未知费用和显式恢复。后台整理另以真实Go API、Pi Worker和AgentTask队列验证两个独立Review来源、一次无工具调用、候选-only发布、重启幂等、关闭设置后不再生成任务，以及来源或结果变化阻止发布。

浏览器与组件测试验证发送说明、比较数量、关系建议/版本过期展示、模型调用、保存候选及独立审核；Go测试还验证已确认比较目标在版本变化或来源不可用后不能继续确认新候选。Proxy验证公开命令允许、私有上下文不转发。

合成测试证明执行、版本和权限边界，不证明模型识别语义冲突的准确率、经验质量、长期噪声控制或跨任务泛化。真实模型关系质量、held-out 与召回基准仍是后续工作。Phase 3 保持部分实现。
