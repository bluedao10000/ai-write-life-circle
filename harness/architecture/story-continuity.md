# 对话创作的故事连续性

灵感对话以作品级创作资产保存作者设定，以会话级讨论焦点保存当前目标。Pi Thinking 在每次请求及恢复时读取最新状态，模型决定需要补读哪些材料、如何推进讨论，并通过受控工具记录本轮变化。Go 是设定、版本和变更回执的唯一权威。

## 每轮流程

```text
作者消息 → Pi 持久接受消息和 Run
  → Go 按 creative scope 提供最新故事上下文
  → Pi 将上下文、原始消息编号与近期对话纳入输入预算
  → 模型按需读取资产、原始讨论、章节或分析方法
  → record_story_changes：一次原子保存本轮决定/备选/否定/暂缓
  → update_discussion_focus：保存本会话的讨论目标与相关资产
  → 回复作者；界面独立读取变更回执
  → 后台整理补充尚未记录的候选
```

开启“随聊记录设定”同时允许会话读取创作资料；此开关独立于后台整理授权、模型和暂停状态。记录使用当前 Thinking 模型，工具本身不发起额外模型请求。关闭记录后仍可读取已授权的故事上下文。创作工具只修改设定和讨论焦点，正文仍通过写作编辑器修改。

## 内容与权威

| 作者表达 | 保存结果 | 下一轮的使用方式 |
| --- | --- | --- |
| “主角叫林舟，是法医” | `decide` → accepted 资产及来源 | 作为作者当前设定 |
| “改成记者，动机不变” | 目标资产 CAS 更新，只修改明确字段 | 读取新版本，保留未改字段 |
| “也许父亲是叛徒，先作备选” | `explore` → proposed 候选 | 保留可能性，不作为事实 |
| “不要这条线” | `reject` → 拒绝候选；撤回设定需明确字段补丁 | 不主动复活已否定方向 |
| “母亲失踪原因以后再说” | `defer` → open_question / deferred | 保留问题，等待作者重启讨论 |

`story_intent` 保存题材、主题和创作方向，沿用现有资产字段与版本机制。`questionStatus` 只用于 `open_question`，支持 pending、deferred、resolved。作者决定、模型建议、正文观察与角色观点的权威不同，不能相互替代。逐字引文验证来源；语义是否构成决定由模型判断。

每本书共享作品方向、已确认设定、候选和问题。讨论焦点包含 goal、assetIds、questionIds、suggestedNextStep 和版本，按 sessionId 保存。新会话继承作品设定，不继承其他会话的局部目标。

## 上下文选择

Go 返回有界的最新状态，优先作品方向、当前点名/别名命中的资产、本会话焦点、关联资产及最近变化；资产只使用当前版本，归档和被替代内容不进入当前设定。候选、否定与问题单独分区。Pi 再按模型预算压缩视图，保留来源类别、版本和省略数量；缺少细节时使用现有读取工具。压缩摘要不具有原始引文的证据效力。

关键实现：`creative/story.go`、`thinking/story_tools.go`、`agent/src/tools/story-context.ts`、`agent/src/runtime/pi-host.ts`。

## 保存、恢复与撤销

- `record_story_changes` 接收 1–8 条变化，每条附原始 messageId 与逐字引用，必须包含当前作者消息。Host 提供可信的外层 messageId/runId；Go 核对实际运行快照和授权后提交。
- 每个逻辑作者消息只提交一批变化；Pi 检查点保存工具参数与结果。回复中断或恢复不会再次创建资产。校验和版本冲突作为可处理的工具反馈；结果未知时保留原参数用于恢复。
- 回执与回复分别持久化。即使回答失败，前端仍按原始消息展示保存结果；只有成功回执才能支持“已保存”的表述。
- 撤销检查全部受影响的当前版本，冲突时整批不变。修改的撤销生成新版本，新建资产的撤销将其归档，候选恢复原状态。不会覆盖随后人工编辑的内容。
- 后台整理收到已记录变化，只补充缺漏候选；确定性去重避免把同轮已保存字段再做成待审核候选。会话删除清除讨论焦点和引用原文，已接受设定保留并标注来源会话已删除。

公开 API 见 [story-context-api-v1.json](../contracts/story-context-api-v1.json)，私有工具见 [thinking-internal-v1.md](../contracts/thinking-internal-v1.md)。新增状态沿用 creative 的原子 JSON 与文件锁；读取旧状态时初始化新增集合。

## 验证

`pnpm test:story` 使用真实 Go、Pi SDK 和合成 HTTP 模型，验证多轮创建/补充/修改、候选/否定/暂缓、跨会话状态、失败后的保存、恢复幂等和撤销。Go 单测覆盖来源、授权、版本冲突与后台去重；React 测试覆盖失败回复的回执、开关、撤销及切换作品的响应隔离。

这些测试验证工程行为。真实模型的意图识别与创作帮助程度用 [对话样例](../evals/thinking-agent/story-continuity.json) 人工复核，不能由固定模型替身的通过结果推断。
