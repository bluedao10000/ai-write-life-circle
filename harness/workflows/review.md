# 连续性与风格审查

输入：指定范围及审查维度。记录实际读过的文件和未覆盖范围。

检查：人物动机与成长依据、视角人物知识边界、时空可达性、世界规则代价、主支线因果和悬置、伏笔状态、作者意图与读者可感知效果。

风格检查：叙事视角、叙述距离、节奏、用词、对白、意象。只使用作者确认的风格基线。刻意变化不等于错误。

输出 reviews/：严重度（阻断、疑问、偏好）、问题、原文位置、对应规则证据、至少一种不代写的修复方向、置信度。

区分客观矛盾与审美建议。缺证据写「待判断」。不自动润色，不强制统一角色口吻。无基线时先请求样本。

## CI 检查

日常 CI 在 PR 和 main push 时执行：类型检查、Lint、OpenAPI 可重现性、Go 与 Web 单元测试；新提交会取消同一 PR 的旧检查。开发分支 push 不再重复运行一套 CI。

耗时的全量集成、Go Race、Agent Eval、10/100/500 章回填、Docker、Lighthouse 和浏览器 E2E 已移到 GitHub Actions 的 `Full Regression (Manual)`，按需选择目标分支手动运行。快速 CI 通过不代表这些完整回归已执行。
