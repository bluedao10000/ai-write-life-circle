# 接受提案

输入：作者明确指定提案 ID 与接受条目。

1. 核对提案来源 hash 与当前正文。检查相关文件有无作者新改动。过期则停止该条，重新评估。
2. 只应用接受条目，保留未接受内容。不把「不错、再看看」视为整批接受。
3. 按影响清单更新正式档案和索引。记录决策依据、旧状态、新状态及被取代条目。
4. 追加 decisions/log.md，标记提案各项状态，更新 state/current.md。
5. 复核相互引用、状态和正文未改动。一个逻辑变更用一个 Git commit。未授权提交时展示 diff。

中途中断：先核对已修改文件与决策记录，再继续，不重复添加。回退通过新提交撤销指定变更，避免 reset 覆盖作者工作。

自动正文观察、索引整理与来源失效不属于需要逐条接受的正式设定提案。作者只在需要创作裁决时选择是否处理；AI 观察不能冒充作者 confirmed。按需纠错是独立、可撤销的记录，不修改正文或 Harness。见 [AI 作品记忆](../architecture/ai-knowledge-memory.md)。
